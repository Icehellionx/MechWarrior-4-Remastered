# MW4 research baseline

Updated: 2026-09-17. This file separates observed evidence from hypotheses; it is not a compatibility claim.

Correction after field testing: every earlier “responsive window” or “empty log” result below is structural/process evidence only. The user reproduced the legacy incorrect-install dialog for all three games, and that dialog satisfied the old smoke predicate. No title is runtime-qualified until a dialog-aware test reaches an actual menu and gameplay path.

## Observed local media evidence

Both local Inner Sphere and Clan Mech Pak ISOs contain `CDAC14BA.DLL`/`CDAC21BA.DLL`, `SCSHD.CSA`, `SCSHD.EXE`, and `SECDRV.SYS`, alongside pack-specific resource/map/mission payloads and official Patch 3 installers/data. This is consistent with C-Dilla/SafeCast-era DRM and contradicts the tentative “16-bit encryption” description as currently stated.

Static inspection narrows that diagnosis: the pack setup engines and protected components are 32-bit x86 PE files, but the Clan `SCSHD.exe` explicitly references `CDILLA16.EXE`, the `\\.\pipe\C-Dilla\Srv` service endpoint, `\\.\C-Dilla`, and C-Dilla licence registry keys. The likely 64-bit break is therefore an obsolete C-Dilla/SafeCast activation stack containing a 16-bit helper, not 16-bit encryption of the game assets. This remains a static-evidence conclusion until reproduced in an isolated reference environment.

The actual pack data is directly readable and not encrypted: Inner Sphere exposes 10 `RESOURCE` files totaling 34,434,947 bytes, and Clan exposes 10 totaling 20,285,495 bytes. Each contains two maps plus mission metadata/assets. Neither pack payload collides with the staged Vengeance or Black Knight trees. Six names collide with Mercenaries, but four of those Mercenaries files differ by hash; blindly overlaying the retail pack payload onto Mercenaries would therefore overwrite later/different content and is not acceptable.

Both on-disc readmes say the packs add content to Vengeance and Black Knight, require Vengeance, must be reinstalled after Black Knight to become visible there, and automatically apply Vengeance Patch 3 or Black Knight Patch 1. The setup DLLs look up `HKLM\SOFTWARE\Microsoft\Microsoft Games\MechWarrior Vengeance\Exe Path`, while the disc-protection layer separately requests a product key and SafeCast/C-Dilla licensing. This establishes three distinct contracts: plain resource overlay, correct official game patch level, and entitlement/visibility.

The Inner Sphere image also contains a `Razor1911` directory. That directory is third-party crack material and is excluded from any automatic or release input. Its presence means the image cannot be treated as pristine retail media solely by filename.

The entitlement effect is now localized in the patched runtime archives rather than inferred from the obsolete installer. Exact `#VBD` inspection found the same eight nonzero records in both `tables\mechtable.mpt` and `tables\mechchassistable.mpt` in qualified Vengeance Patch 3 `core.mw4`, Black Knight PR1 `corex.mw4`, and Mercenaries PR1 `core.mw4`: Clan flag 1 marks Arctic Wolf, Cauldron-Born, Kodiak, and Masakari; Inner Sphere flag 2 marks Dragon, Highlander, Hunchback, and Zeus. A source-owned transform exact-hash gates those three archives, independently decodes the archive format, zeroes only the selected four-record groups in both tables, and points the original directory entries at appended uncompressed replacements. It never modifies source media, never installs C-Dilla/SafeCast, and applies the selected packs to Mercenaries as well as the shared Vengeance/Black Knight family. Both-pack outputs are deterministic: Vengeance `core.mw4` is 1,255,140 bytes/SHA-256 `6033d799bb8fc1cbc6339f2d7a7ba784657dcc141f0af88be017f21ab8e2f57`; Black Knight `corex.mw4` is 1,448,084 bytes/`019f579955c84fddc12a471e942e7de61ba6076f3a7ca2b47d8ef060759dad60`; Mercenaries `core.mw4` is 1,699,370 bytes/`b20705b26287e106c913d85206727fb8df43cd11696e71f8745a580afc1ea4ef`. This is deterministic structural evidence; Instant Action, multiplayer, and MechLab visibility in each title remain field gates. The original Microsoft description scoped pack availability to those modes, so campaign shops are intentionally unchanged.

Black Knight contains a conventional game payload (`MW4X`, `RESOURCE`, movies), `SECDRV.SYS`, and an official Vengeance Patch 2 payload. Its disc `MW4X.EXE` and historical local replacement both report version `45.05.10.0701` and have the same length but different hashes. The replacement was useful comparison evidence but is no longer accepted by the install plan and is not a project asset.

Vengeance Disc 1 contains a SafeDisc loader (`MW4.exe`, SHA-256 `b129d968…`) and the real version `01.06.11.0220` game image in `MW4.ICD`. A previously supplied replacement executable is version `01.20.07.2403`, matching the official 2.0 patch generation, but it is now comparison evidence only and is not an installer input. The version 2.0 RTP data names the installer mappings `AUTOCO~1.EXE` → `AutoConfig.exe`, `SCRIPT~1.DLL` → `ScriptStrings.dll`, and `MISSIO~1.DLL` → `MissionLang.dll`.

The original retail loader/ICD/DPLAYER set deterministically produces a disc-free version `01.06.11.0220` executable. Static and emulated analysis derived the four exact block-cipher words after validating 192 of 194 legacy imports. The reviewed managed implementation removes the 1.50.20 page-local second layer, repairs imports and protected pointers, canonicalizes inert legacy padding, normalizes the raw end, and changes one uniquely matched conditional disc-check branch. Its 3,497,984-byte result has SHA-256 `48ba4baf0894f0c14c44ddaf503cf953f59be3b919817156f1f11ea9b0df0de4`. This proves reproducibility, not a valid installation or gameplay path. Exact input hashes fail closed, and no historical unwrapper or emulator is a product dependency.

The 40,042,724-byte official Patch 3 RTP on Inner Sphere media applies directly to the original retail tree; applying Patch 2 first produces the same Patch 3 outputs except for Patch-2-only `drvmgt.dll`. The patched loader/ICD retain SafeDisc 1.50.20 but use different validated cipher metadata. The exact-input managed transform produces a deterministic 3,698,688-byte executable with SHA-256 `9ad88d307bf666c76ffd953aba3ebff6069a87e3c36b81d674f5668acb4dd7f3`, removes the `CdaC14BA.dll` and `ARTPCLNT.dll` import descriptors, and replaces exactly two deferred calls to each legacy client while explicitly cleaning their stack arguments. The earlier v1 replacement corrupted the caller stack and caused a delayed incorrect-install stop; a fresh packaged v2 tree remained responsive with an empty game log. `third_party/VengeancePatch3.lock.json` records the exact user-media inputs and retained outputs.

The two recognized Vengeance discs plus that exact replacement produced a 231-file, 1.04 GB disposable full-install tree without running legacy setup or SafeDisc. Its ownership manifest verifies every length and SHA-256; setup/DRM files are absent and optical-media read-only flags are cleared. Runtime behavior is still unqualified.

Black Knight PR1's launch-time app-local loader is disproven: upstream SafeDiscLoader2 intercepts child creation and injects into SafeDisc's temporary process, where the field path faulted. The source-built GPL DLL SHA-256 `7fbf1fbd…` is therefore used only inside setup-owned scratch to capture the already decrypted image from exact protected PR1 input `be9c1573…`; neither the DLL nor its configuration or mapped image is installed.

Static v2 `04fe9acf…` failed at removed address `0x008A3504`; v3 `7761c41d…` repaired the 127 qualified tail branches and import-table order but was still field-disproven by a frame-one jump into stack memory. The remaining defect was not the renderer: v3 rewired 108 indirect CALL/JMP operands and two entry-point MOV operands to the wrong canonical imports. The MOV loads in particular became `SendMessageA` instead of `InsertMenuItemA` and `EnableMenuItem`. Transform v4 exact-validates and corrects those 110 code operands, retains the 127-branch/residual-tail checks, declares five ordinary sections, and truncates both SafeDisc tails. It deterministically emits 3,743,744-byte `MW4x.exe` SHA-256 `b31bd0518311eb88e0f94a38e7b5a7ee6e98f4431f8cf585276b3df1166b8a1e`; its `.text` matches the retained working structural layout except for the two deliberate setup-validation replacements and one stricter related branch. A production-shaped dgVoodoo tree with videos enabled remained correctly titled and responsive for 60 seconds. Focused intro/menu, Alt-Tab, pilot creation, mission load, complete coordinator cleanup, package, and Defender qualification remain open. Retail Black Knight remains rejected because its separate Vengeance Patch 2 prerequisite is not implemented.

The supplied Mercenaries Disc 2 is UDF media that `bsdtar` did not enumerate but Windows mounted successfully. It contains the expected movie/map/mission payload plus a third-party `Crack/` directory and `SECDRV.SYS`; both are detected and excluded by policy. All seven images match distinct structural descriptors through read-only Windows mounts.

Mercenaries Disc 1 stores 85 `GAME/RESOURCE/...` payload entries in `MSGAME.CAB`; a containment-first extraction reproduced exactly those 85 files (615,038,509 bytes) without running setup. The disc SafeDisc image reports version `50.06.09.3002`. The exact retail loader/ICD/DPLAYER inputs now produce a deterministic 3,895,296-byte executable with SHA-256 `039b5781f2b920b07c69edd91b8719a27930770d441e989b79d9aa5f41619cdc`. The managed transform uses the title's distinct second-layer modifiers and import seeds, repairs protected pointers/imports, removes only the `CdaC14BA.dll` descriptor and uniquely matched title gate, and redirects the two setup-record root arguments from machine-wide HKLM to 32-bit per-user HKCU without changing code size. Process tracing proved the original machine-wide product-key lookup immediately emitted the incorrect-install stop. The redirected runtime plus its launcher-owned HKCU record remained responsive for 35 seconds with an empty game log and no elevation.

The supported Mercenaries route advances that retail tree to official PR1 before commit. The exact 5,376,000-byte `mercpr1.exe` nested in the common fix ZIP is hash-gated; intake retains only its qualified `Patchw32.dll` and `English/MW4MERCS.RTP` and excludes the adjacent historical no-CD payload. The source-owned RTP host applies all 11 qualified official changes in contained scratch. A PR1-specific managed SafeDisc transform then repairs the `50.07.01.2105` image, bypasses both C-Dilla setup gates, both EULA/setup validation calls, both installed-media checks, and both obsolete AutoRTPatch calls, and removes the `CdaC14BA.dll` and `ARTPCLNT.dll` imports. Its deterministic 3,915,776-byte output has SHA-256 `7a806308fb3ebdaf1270845faa518d2ad708dce85f6c747ab9d9331c3ea505b5`. A fresh `e054d34` production-worker smoke used extracted copies of the original two ISOs plus the original fix ZIP, exact-verified a 211-file ownership manifest, left no transform scratch, passed Defender, and wrote the narrow 32-bit registration. The launcher argument profile produced one responsive `MechWarrior Mercenaries` window and no visible EULA, `STOP`, fullscreen, CD, or incorrect-install dialog. Normal ownership-safe removal deleted 212 owned paths and the project-owned registration values while preserving `Mechwarrior4.txt`, `options.ini`, and a synthetic save. Elevated packaged ZIP/ISO intake, actual menu/gameplay, and reference-registry parity remain unproven.

## External evidence

- [Archived Microsoft support article 325999](https://www.betaarchive.com/wiki/index.php/Microsoft_KB_Archive/325999) describes missing pack logos/content, install-order interactions, and an official CD-dependent SafeCast Repair Utility. It corroborates that payload presence and SafeCast entitlement are separate conditions.
- [Microsoft's surviving disc-check support article](https://support.microsoft.com/en-us/topic/error-message-or-the-game-stops-responding-on-the-loading-screen-when-you-start-a-microsoft-game-please-insert-the-correct-cd-rom-c9eb279d-e016-c079-6afa-5bb37dfc1018) names the Inner Sphere pack among protected products and directs users to launch it with Vengeance Disc 1 or Black Knight media.
- Microsoft community reports show Vengeance failing after pack installation on 64-bit Windows and recovering when packs are removed; these are useful reports, not root-cause proof.
- The 2010 free release was specifically a Microsoft-cleared MekTek distribution of MechWarrior 4: Mercenaries. That does not by itself prove the original Vengeance, Black Knight, retail Mercenaries, packs, or arbitrary mirrors remain freely redistributable today.

## Working hypotheses

1. The implemented safe path extracts only validated Microsoft pack payloads, applies the matching official patch resources, and replaces the obsolete table flags reproducibly without installing DRM drivers; its remaining gate is field roster visibility.
2. Exact per-game core/resource differences and install-order effects must be derived from clean before/after trees, not assumed from community replacement files.
3. Patch 3 demonstrably supplies the shared runtime/data update and can launch with the Inner Sphere resources while legacy SafeCast files are absent. The two table flags are the only remaining localized entitlement markers found in all three final archives; actual game visibility must still be proven.

## Open-source patch-tool evaluation

`bwrsandman/rtptool` revision `258d1750340917bcf1361a177b90abd16de40453` is MIT-licensed and conceptually fits the desired checksum-verified transform. Evaluation found that version 0.1.1 does not parse the supplied files: the 2.09 Vengeance payload misparses a negative entry count and the pack payload reports format version `0x025a`, newer than the tool's supported `0x0209`. Its CLI also joins untrusted record names directly to output paths. Do not vendor or invoke it in the product without format fixes, path containment, adversarial tests, and independent output comparison.

`elishacloud/dinputto8` is a current Zlib-licensed DirectInput 1–7 to DirectInput 8 proxy. Official tag `v1.1.100.0` resolves to commit `46e7ea7b76dd64ea1066f899212e2102774cc0d2`; its 272,384-byte x86 `dinput.dll` has SHA-256 `f96bb1101e23a6477043a3859cbf875a990eaa62ee6849f87e967b3dd963f781`, reports file version `1.1.110.0`, and the matching tagged source ZIP has SHA-256 `823ce9b2885c4e4546a8197cbd4618b9ee85d5e00f1326608c3a162102623ac5`. Binary plus source produced zero current Defender detections. In a disposable final-static Black Knight/dgVoodoo tree, the wrapper loaded from `MW4X\dinput.dll` and Black Knight remained correctly titled/responsive for 15 seconds without `/gosNoJoystick`. This proves only load compatibility. Upstream issue 22 records Mercenaries crashes on a second mission and when rebinding during a mission; the issue is closed without visible resolution. Vengeance and Mercenaries attempts used superseded DDrawCompat evidence trees and reached generic error dialogs, so they are inadmissible for the current renderer stack. Do not package the wrapper or remove `/gosNoJoystick` until all three exact final trees pass pilot creation, two consecutive missions, in-mission binding, joystick/HOTAS, keyboard/mouse, and Alt-Tab interactively.

## Falsifying checks

- Diff clean Vengeance and Black Knight trees before/after each pack on a controlled 32-bit reference environment if needed.
- Trace registry/file writes from the original pack setup in an isolated VM.
- Prove each direct-extraction candidate produces the same owned files and game-visible pack markers without loading/installing legacy drivers.
